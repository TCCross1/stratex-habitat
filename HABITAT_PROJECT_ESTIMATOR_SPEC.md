## 1. Executive Summary & Core Mission

The **Habitat Project Estimator™** is an evidence-aware estimating agent embedded directly within the **Habitat Design Studio 2.0**. It represents the financial intelligence layer of residential renovation, empowering homeowners with transparent, localized, and multi-scenario cost ranges *before* they request contractor bids.

### 1.1. Core Mission
Historically, home renovation estimates suffer from two extremes: the oversimplified, inaccurate "broad price per square foot" and the complex, intimidating, black-box bid that conceals margins, assumptions, and quality trade-offs. 

The Habitat Project Estimator™ resolves this by:
* Generating **transparent, detailed, assembly-based cost projections** based on real material SKUs and regional labor indices.
* Categorizing and presenting costs across **National, Regional, and Localized levels** depending on data fidelity.
* Never representing a planning estimate as a binding bid, final construction price, or professional engineering opinion.
* Maintaining a supportive, educational, non-alarmist tone ("always explain, never alarm") to demystify contractor margins and risk contingencies.

## 2. The Core Cost Equation

Every estimate is generated by modeling physical reality through a cascading cost formula. No numbers are arbitrary; every line item must trace through this mathematical framework.

```
+-----------------------------------------------------------------------------------+
|                           THE CORE COST FLOW MODEL                                |
+-----------------------------------------------------------------------------------+
|  [ DIRECT COST ]                                                                  |
|  Materials + Labor + Equipment + Subcontractors + Delivery/Mobilization          |
|  + Permits/Fees + Waste/Productivity Adjustments                                  |
|                                                                                   |
|                                         | (+ Contractor Overhead)                 |
|                                         v                                         |
|                                                                                   |
|  [ CONTRACTOR COST ]                                                              |
|  Direct Cost + Overhead (General & Project-Specific)                              |
|                                                                                   |
|                                         | (+ Profit, Contingency, & Taxes)        |
|                                         v                                         |
|                                                                                   |
|  [ SELLING PRICE ]                                                                |
|  Contractor Cost + Profit + Contingency + Applicable Taxes                        |
+-----------------------------------------------------------------------------------+
```

### 2.1. Mathematical Formula Representation

$$\text{Direct Cost} (DC) = \sum_{i} \left( Q_i \times M_i \times (1 + W_i) \right) + \sum_{j} \left( H_j \times L_j \times B_j \times \prod C_k \right) + E + S + D + P$$

$$\text{Contractor Cost} (CC) = DC \times (1 + OH_{gen}) + OH_{proj}$$

$$\text{Selling Price} (SP) = \left( CC \times (1 + P_{profit}) + K_{contingency} \right) \times (1 + T_{tax})$$

Where:
* $Q_i$: Quantity of material $i$ extracted from Design Studio.
* $M_i$: Base material unit SKU cost.
* $W_i$: Waste factor for material $i$.
* $H_j$: Estimated labor production hours for trade $j$.
* $L_j$: Regional wage basis for trade $j$.
* $B_j$: Labor burden multiplier (benefits, FICA, insurances).
* $C_k$: Labor complexity multipliers (height, occupancy, winter).
* $E$: Equipment requirements (scaffolding, compactors, dumpsters).
* $S$: Specialized subcontractor costs.
* $D$: Delivery and mobilization costs.
* $P$: Permits and regulatory fees.
* $OH_{gen}$, $OH_{proj}$: General and project-specific overhead percentages/allowances.
* $P_{profit}$: Target profit percentage.
* $K_{contingency}$: Contingency buffer based on information missingness.
* $T_{tax}$: Local sales and transaction tax.

## 3. System Subsystems Architecture

The Estimator is comprised of twelve modular engines working in unison to translate a 3D digital model into a comprehensive financial plan.

```
                          +------------------------+
                          |   Design Studio 2.0    |
                          +-----------+------------+
                                      |
                                      v
                          +------------------------+
                          | Quantity Takeoff Engine| <--- Property DNA
                          +-----------+------------+
                                      |
                                      v
                          +------------------------+
                          | Assembly Cost Library  | <--- Material Library
                          +-----------+------------+
                                      |
                                      v
                          +------------------------+
                          |  Regional Cost Engine  | <--- ZIP Code / GIS
                          +-----------+------------+
                                      |
                                      v
                          +------------------------+
                          | Labor & Overhead Model |
                          +-----------+------------+
                                      |
                                      v
                          +------------------------+
                          |  Confidence Framework  |
                          +-----------+------------+
                                      |
                                      v
                          +------------------------+
                          |   Explanation Engine   |
                          +-----------+------------+
                                      |
                                      v
                          +------------------------+
                          |   Cost UX Panel / API  |
                          +------------------------+
```

1. **Quantity Takeoff Engine (`QUANTITY_TAKEOFF_ENGINE.md`)**: Automatically extracts dimensions and areas from the Digital Twin, labeling each with an explicit source.
2. **Assembly Cost Library (`ASSEMBLY_COST_LIBRARY.md`)**: Groups materials, labor, equipment, and factors into reusable, dynamic assemblies (e.g., Stamped Concrete Patio).
3. **Regional Cost Engine (`REGIONAL_COST_ENGINE.md`)**: Modulates material, labor, logistics, and permit costs using regional geographic multipliers based on ZIP code.
4. **Labor Productivity Model (`LABOR_PRODUCTIVITY_MODEL.md`)**: Calculates labor hours based on trade classifications, crew compositions, and complexity factors.
5. **Overhead and Profit Model (`OVERHEAD_AND_PROFIT_MODEL.md`)**: Distributes transparent planning allowances for contractor operations and reasonable margins.
6. **Estimate Confidence Framework (`ESTIMATE_CONFIDENCE_FRAMEWORK.md`)**: Grades the estimate's reliability across four tiers (Verified, Estimated, Suggested, Preliminary) and recommends clarifying steps.
7. **Estimate Explanation Engine (`ESTIMATE_EXPLANATION_ENGINE.md`)**: Translates changes in materials, dimensions, or locations into clear, natural-language "Why" explanations.
8. **Contractor Proposal Variance (`CONTRACTOR_PROPOSAL_VARIANCE.md`)**: Side-by-side comparative analysis of incoming contractor bids against the planning baseline.
9. **Cost Intelligence UX (`COST_INTELLIGENCE_UX.md`)**: UI specification for the high-contrast Stratex dashboard.
10. **Estimator API (`ESTIMATOR_API.md`)**: API gateway endpoint contracts for real-time recalculations.
11. **Estimate Test & Validation Plan (`ESTIMATE_TEST_AND_VALIDATION_PLAN.md`)**: Diagnostic test suite ensuring reproducibility, boundary checks, and system accuracy.

## 4. Engineering Laws of OPERATION HABITAT

All systems and developers working on the Habitat Project Estimator™ must enforce these structural rules. Code changes or data structures that violate these laws are rejected.

1. **No Estimate Without a Pricing Date**: Every generated estimate must stamp `pricing_date` (ISO 8601). Prices are volatile; cost structures expire after 90 days.
2. **No Estimate Without a Geographic Basis**: Every estimate must define its `geographic_basis` (ZIP code or localized latitude/longitude) to calculate regional multipliers.
3. **No Quantity Without a Declared Source**: Every single measurement must declare its source (`Verified Property Data`, `Digital Twin Measurement`, `Homeowner Input`, `AI-Derived Measurement`, `Template Allowance`, or `Unknown`).
4. **No False Precision**: Do not present a rough, TIER 3 estimate as `$4,281.34`. Round to appropriate confidence-based intervals (e.g., `$4,100 - $4,500`) to reflect systemic uncertainty.
5. **No Hidden Assumptions**: All active site assumptions (e.g., "Assumes soil compaction is normal, no rock excavation included") must be fully exposed in the output metadata.
6. **Unknown Conditions Must Remain Visible**: Instead of ignoring what we don't know (e.g., soil composition, sub-slab utility lines, framing rot behind siding), the system must represent these as visible "Risk Allowances" with suggested verification actions.
7. **Dynamic & Instant Recalculation**: Any change to a material SKU, dimensions, or regional constraints must immediately trigger the recalculation pipeline within $<200$ milliseconds.
8. **Reproducibility**: Every estimate must be 100% reproducible from its saved inputs, rules, factors, and price-book version.

## 5. Ecosystem Integrations

The Habitat Project Estimator™ does not operate as a standalone database; it is a collaborative tissue intersecting key components of the Habitat environment.

* **Design Studio 2.0**: Reads the active 3D/PBR model canvas coordinates and zone selections to trigger real-time recalculations.
* **Project Library**: Sources standardized templates (e.g., ADU, Deck, Patio) to pre-populate suggested assemblies before individual homeowner modifications are entered.
* **Material Library**: Pulls manufacturer specs, durability profiles, warranties, and unit SKU prices, dynamically updating material cost offsets.
* **Digital Twin & Property DNA**: References read-only physical facts (wind load zones, seismic hazards, existing structural siding, lot topography) to automatically apply labor or contingency multipliers.
* **Project Budget Engine**: Shares estimated scenarios to feed affordability calculators, HELOC loan amortizations, and milestone cash schedules.
* **Build Ready Workflow**: Feeds finalized, high-confidence (TIER 1/2) estimates into permit export packages and structural packages.
* **Project Opportunity Engine**: Package the planning estimate alongside homeowner design preferences to create high-quality, pre-scoped request-for-proposals (RFPs).
* **Contractor Experience**: Provides contractors with the original planning assumptions to help them construct more competitive bids, while remaining a private planning reference that cannot be used to squeeze margins.

*Note: All estimating records and design concepts remain distinct, isolated planning records. Under no circumstances do they modify canonical, immutable Passport historical facts.*
